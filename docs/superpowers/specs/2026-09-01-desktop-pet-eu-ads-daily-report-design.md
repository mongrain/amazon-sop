# 桌宠欧洲站广告日报（12:20）

日期：2026-09-01  
状态：已确认设计，待写实现计划

## 背景

桌宠目前只在 12:30 / 18:10 提醒记任务，不拉广告数据。运营需要每天中午看欧洲站广告曝光、点击、出单是否在涨，并拿到可执行建议，但暂不自动改广告。

## 目标

1. 每天 **12:20** 桌宠通知并打开汇报窗
2. 通过 **yanjun MCP** 拉取欧洲站（UK / DE / FR / IT / ES）近 **7 个完整自然日**的广告汇总
3. 用一张表展示：行 = `国家 · 指标`，列 = 日期；相对前一日上涨在最右列标 `↑`
4. 底部给出 3～5 条**只读**优化建议，由人手动执行

## 非目标

- 不自动暂停、改价、改预算、改否定词
- 不展示活动 / 关键词 / 搜索词明细（本版只要国家汇总）
- 不掺 ASIN 级访客数、总销售额等非广告口径
- 不改动现有 12:30 / 18:10 记任务流程
- 不做 Cursor Automation 替代桌宠汇报
- 不把 yanjun token / 网关密钥暴露给渲染进程以外的配置面（密钥只在主进程 / 环境变量）

## 决策摘要

| 项 | 选择 |
|----|------|
| 实现路径 | 方案 1：桌宠到点拉数并展示 |
| 动作级别 | A：只汇报 + 建议，不自动改广告 |
| 站点 | UK / DE / FR / IT / ES |
| 对比 | 每天相对前一日；涨标 `↑` |
| 表格形态 | C：行 = `国家 · 指标`，列 = 日期 |
| 指标 | 曝光、点击、出单（广告订单） |
| 日期窗口 | 最近 7 个完整自然日；当天半日不进主表 |
| 建议 | 3～5 条，标注「需手动执行」 |

## 架构

```text
12:20 定时触发（桌宠主进程 reminder loop）
  → 系统通知 + 打开「欧洲站广告日报」窗
  → 主进程 callYanjunTool（复用 service/yanjun-mcp 调用方式）
       1) ad_auth_shops → 过滤欧洲站 profile
       2) 按 profile / 国家拉近 7 完整日广告活动报告并汇总
  → 组装矩阵：国家×指标×日期 + 行级涨跌标记
  → 规则引擎生成只读建议
  → 渲染进程展示表格 + 建议
  → 可选：手动「刷新」重拉
```

- 拉数与建议生成在 **Electron 主进程**
- 渲染进程只收结构化结果（表格矩阵、建议列表、错误信息）
- 网关地址来自环境变量（如 `YANJUN_MCP_URL`），与 OMC 服务端配置一致；未配置则提示「未配置领星网关」

## 表格结构

### 行

固定顺序，每个国家 3 行：

1. `{CC} · 曝光`
2. `{CC} · 点击`
3. `{CC} · 出单`

国家顺序：`UK → DE → FR → IT → ES`。某站无授权或无数据时，该国三行显示空/「—」，并在页脚说明。

### 列

- 近 7 个完整自然日，从早到晚（按各站点当地日期对齐到日历日；汇报文案注明时区口径）
- 最右列：`涨跌`——该行最右侧完整日相对前一日：上涨标 `↑`，持平与下跌不标

### 单元格

- 整数展示（曝光 / 点击 / 出单）；缺失为 `—`
- 不做活动级展开

## 数据口径

| 指标 | 含义 | 来源 |
|------|------|------|
| 曝光 | 广告 impressions | 领星广告活动报告汇总 |
| 点击 | 广告 clicks | 同上 |
| 出单 | 广告归因订单数 | 同上（广告订单，非 ASIN 总订单） |

汇总规则：

1. `lingxing_ad_auth_shops`（或 yanjun 等价动态目录工具）取授权店
2. 过滤 `country/marketplace` ∈ {UK, DE, FR, IT, ES}（含常见别名如 GB→UK）
3. 对每个 profile，按日拉取广告活动报告，将该国当日所有活动的曝光/点击/出单相加
4. 拼成 7 日矩阵后计算行级 `↑`

失败处理：

- 全部失败 → 窗内错误条，保留上次成功缓存（若有）
- 部分国家失败 → 成功国家正常展示，失败国家标「拉取失败」并列入页脚

## 交互

| 时间 / 动作 | 行为 |
|-------------|------|
| 每天 12:20 | 通知「欧洲站广告日报到了」；打开汇报窗并自动拉数 |
| 点击通知 / 宠物相关入口 | 打开同一汇报视图 |
| 刷新按钮 | 重新拉数；加载中禁用 |
| 与记任务关系 | 独立 prompt/key（如 `euAdsReport`），不覆盖 tasks/progress |

汇报窗布局（自上而下）：

1. 标题 + 数据窗口说明（7 完整日、欧洲站、只读建议）
2. 表格
3. 「今日建议」列表
4. 页脚：拉取时间、失败站点、手动刷新

## 建议规则（只读）

输入：各国「最近完整日 vs 前一日」的曝光 / 点击 / 出单变化。

输出：最多 5 条，每条含：国家、依据数字、建议动作、复核条件；文案固定带「建议，需你手动执行」。

示意映射（可在实现时微调阈值，但语义不变）：

| 信号 | 建议方向 |
|------|----------|
| 曝光↓ 且 点击↓ | 查预算是否撞顶、出价是否偏低 |
| 点击↑ 且 出单↓ | 查搜索词相关性 / Listing 转化 |
| 曝光↑ 且 点击持平或↓ | 查 CTR、主图/标题吸引力 |
| 三项均↑ | 标为健康，建议观察或谨慎加预算 |
| 出单↑ 但花费效率未知 | 只提示「出单改善」，不臆造 ACoS 结论 |

本版不调用写广告接口；不调用 `diagnose_yesterday_ads` 整店诊断作为唯一数据源（可后续增强，首版以国家日汇总为准）。

## 配置与依赖

- 桌宠需能读到 `YANJUN_MCP_URL`（或同等配置）
- 依赖本机桌宠进程常驻；关机则不提醒
- 复用现有 `callYanjunTool` 解析逻辑；若桌宠目录不便直接 require 根目录 `service/`，允许抽一层共享或在桌宠内复制最小调用封装（实现计划里二选一，优先复用）

## 测试要点

1. 12:20 触发不影响 12:30 记任务
2. 表格行列顺序正确；涨跌只标 `↑`
3. 无欧洲授权店时友好错误
4. 部分站点失败时其余站点仍展示
5. 未配置网关时不崩溃
6. 建议区始终只读文案，无「已执行改价」类误导
